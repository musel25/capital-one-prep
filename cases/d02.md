## Part 2 — Concrete technical exercise

The interviewer now supplies a specific input and a fixed contract. Follow these rules for the technical exercise even if you proposed a different product policy above. You are reviewing an existing implementation, which may violate the contract.

### A. Required behavior and supplied input

Amounts are positive integer cents. Accounts exist and `source != target`. Every rejected operation must preserve all balances and the complete history. An accepted operation moves money and adds one history entry. Validate in this order: target is active, then sufficient funds.

Initial state: A=8000 active, B=2000 inactive, C=0 active; history=[]. Manually process t1=(A,B,3000), t2=(A,C,6000), t3=(C,A,500).

### B. Existing code — trace it as written

The supplied rows are passed in their displayed order. Do not assume this code implements the contract correctly.

```python
def transfer(accounts, history, tx_id, src, dst, amount):
    if accounts[src]["balance"] < amount:
        return "insufficient"
    accounts[src]["balance"] -= amount
    if not accounts[dst]["active"]:
        return "inactive"
    accounts[dst]["balance"] += amount
    history.append({"id": tx_id, "src": src, "dst": dst, "amount": amount})
    return "ok"
```

### C. Your technical tasks

First derive the **current output** by following the code exactly. Separately derive the **desired output** by applying the contract to the same input. Record intermediate state, then compare the two. Propose corrections and the requested extension on paper, without executing code.

1. Give each actual status, balances after each operation, and final history. Repeat for the desired behavior.
2. Fix the sequential in-memory implementation. Explain why the fix alone does not establish safety under concurrent requests.
3. Implement **account_history(history, account_id)** returning [{"id": ..., "delta_cents": ...}] in original history order; outgoing negative, incoming positive, unrelated omitted. Unknown account or empty history returns []. No mutation.
