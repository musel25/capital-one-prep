### Rules and input

Amounts are positive integer cents. Accounts exist and `src != dst`. Each transaction ID is new; retry deduplication is outside this technical task. Calls run sequentially in memory, and dictionary/list writes do not raise exceptions. Every rejected operation must preserve all balances and the complete history. An accepted operation moves exactly `amount` cents from source to target and adds one history entry with fields `id`, `src`, `dst`, and `amount`. Validate in this order: inactive target → `"inactive"`; otherwise insufficient source funds → `"insufficient"`; otherwise accept → `"ok"`. Exact-balance transfers are allowed.

Initial state: A=8000 active, B=2000 inactive, C=0 active; `history=[]`. Accounts are stored as `{account_id: {"balance": cents, "active": boolean}}`. Each tuple below is `(src, dst, amount)`; its label is `tx_id`. Process `t1=(A,B,3000)`, then `t2=(A,C,6000)`, then `t3=(C,A,500)`. These are three distinct transfer attempts, not retries of the same transaction.

### Current code

Process the supplied input in the displayed order.

```python
def transfer(accounts, history, tx_id, src, dst, amount):
    if accounts[src]["balance"] < amount:
        return "insufficient"
    accounts[src]["balance"] -= amount
    if not accounts[dst]["active"]:
        return "inactive"
    accounts[dst]["balance"] += amount
    history.append({"id": tx_id, "src": src, "dst": dst, "amount": amount})
    return "ok"
```
