## Interview prompt
“A promotion promises a reward on a qualifying purchase. Which edge cases would you clarify before shipping the offer?”

Contrato: promoción válida para 100<=minute<160, amount_cents>=5000, new_customer=True y category='travel'. Reward bruto=5% por compra, floor a centavos, cap acumulado por cliente=300. Procesar en orden de tabla. Usado inicial U=100, V=0.

| id | customer | minute | amount_cents | new_customer | category |
|---|---|---:|---:|---|---|
| p1 | U | 100 | 5000 | True | travel |
| p2 | U | 159 | 6000 | True | travel |
| p3 | V | 160 | 7000 | True | travel |
| p4 | V | 120 | 5000 | False | travel |
| p5 | V | 140 | 5000 | True | grocery |

```python
def eligible(p):
    return (100 < p["minute"] <= 160
            and p["amount_cents"] > 5000
            and p["new_customer"] and p["category"] == "travel")

def awards(rows):
    return [(p["id"], p["amount_cents"] * 5 // 100)
            for p in rows if eligible(p)]
```

1. Give current awards, correct eligibility IDs, and correct capped awards. Keep an eligible zero-award row in the result.
2. Write an eligibility decision table with the boundaries start-1,start,end-1,end and amount4999,5000.
3. Implement **capped_awards(rows, used)**, returning (awards,new_used), without mutating the input used dictionary. Include one customer already at cap. Explain why two simultaneous requests could still exceed the cap without shared-state coordination.
