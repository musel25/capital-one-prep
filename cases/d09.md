## Part 1 — Product discussion

### What you must explain

Give a 60–90 second answer in English. You are explicitly being asked to cover all four items below; they are not hidden requirements:

1. Your proposed approach and any assumptions you would clarify.
2. The customer benefit it is intended to deliver.

### Interview question

“A promotion promises a reward on a qualifying purchase. Which edge cases would you clarify before shipping the offer?”

## Part 2 — Concrete technical exercise

The interviewer now supplies a specific input and a fixed contract. Follow these rules for the technical exercise even if you proposed a different product policy above. You are reviewing an existing implementation, which may violate the contract.

### A. Required behavior and supplied input

The promotion applies when `100 <= minute < 160`, `amount_cents >= 5000`, `new_customer=True`, and `category='travel'`. The gross reward is 5% per purchase, rounded down to whole cents. The cumulative cap per customer is 300 cents. Process rows in table order. Initial usage: U=100, V=0.

| id | customer | minute | amount_cents | new_customer | category |
|---|---|---:|---:|---|---|
| p1 | U | 100 | 5000 | True | travel |
| p2 | U | 159 | 6000 | True | travel |
| p3 | V | 160 | 7000 | True | travel |
| p4 | V | 120 | 5000 | False | travel |
| p5 | V | 140 | 5000 | True | grocery |

### B. Existing code — trace it as written

The supplied rows are passed in their displayed order. Do not assume this code implements the contract correctly.

```python
def eligible(p):
    return (100 < p["minute"] <= 160
            and p["amount_cents"] > 5000
            and p["new_customer"] and p["category"] == "travel")

def awards(rows):
    return [(p["id"], p["amount_cents"] * 5 // 100)
            for p in rows if eligible(p)]
```

### C. Your technical tasks

First derive the **current output** by following the code exactly. Separately derive the **desired output** by applying the contract to the same input. Record intermediate state, then compare the two. Propose corrections and the requested extension on paper, without executing code.

1. Give current awards, correct eligibility IDs, and correct capped awards. Keep an eligible zero-award row in the result.
2. Write an eligibility decision table with the boundaries start-1,start,end-1,end and amount4999,5000.
3. Implement **capped_awards(rows, used)**, returning (awards,new_used), without mutating the input used dictionary. Include one customer already at cap. Explain why two simultaneous requests could still exceed the cap without shared-state coordination.
