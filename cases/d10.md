## Interview prompt
“A company lends equipment from a shared stock pool. How do reservations improve planning, and what customer-facing states would make cancellations understandable?”

Estado: stock={'camera':3,'mic':2}; reservations={}. reserve(id,items) acepta solo si todas las cantidades positivas están disponibles. items es una lista sin productos repetidos; todos existen. En rechazo no cambia stock ni reservations. IDs nuevos.

Operaciones: R1=[('camera',2),('mic',3)], R2=[('camera',2),('mic',1)].

```python
def reserve(stock, reservations, reservation_id, items):
    for product, quantity in items:
        if stock[product] < quantity:
            return False
        stock[product] -= quantity
    reservations[reservation_id] = dict(items)
    return True
```

1. Trace actual results, stock and reservations after R1 and R2. Then derive desired state.
2. Repair reserve without executing. State assumptions needed for this sequential implementation.
3. Add **cancel(stock,reservations,id,cancelled)**: cancelled is initially an empty set; first cancel of an existing reservation restores all its units, records id in cancelled and returns 'cancelled'; repeat returns 'already_cancelled' without changing stock; unknown id returns 'unknown'. Preserve the original reservation record. Trace cancel R2, cancel R2 again, cancel X. Define an invariant across available and active-reserved units.
