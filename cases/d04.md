## Part 2 — Concrete technical exercise

The interviewer now supplies a specific input and a fixed contract. Follow these rules for the technical exercise even if you proposed a different product policy above. You are reviewing an existing implementation, which may violate the contract.

### A. Required behavior and supplied input

Filter by exact status, sort ascending by `(created, id)`, then paginate with `offset >= 0` and `limit > 0`. `total` counts all matching rows. `next_offset` is `offset + len(items)` if matching rows remain, otherwise `None`. The supplied data is already sorted.

Query: `status='open', offset=0, limit=2`.

| id | created | status |
|---|---:|---|
| d1 | 10 | closed |
| d2 | 20 | open |
| d3 | 20 | open |
| d4 | 30 | closed |
| d5 | 40 | open |
| d6 | 50 | open |

### B. Existing code — trace it as written

The supplied rows are passed in their displayed order. Do not assume this code implements the contract correctly.

```python
def page(rows, status, offset, limit):
    ordered = sorted(rows, key=lambda r: (r["created"], r["id"]))
    chunk = ordered[offset:offset+limit]
    items = [r["id"] for r in chunk if r["status"] == status]
    return {"items": items, "total": len(items),
            "next_offset": offset + limit if len(items) == limit else None}
```

### C. Your technical tasks

First derive the **current output** by following the code exactly. Separately derive the **desired output** by applying the contract to the same input. Record intermediate state, then compare the two. Propose corrections and the requested extension on paper, without executing code.

1. Predict the exact response and the correct first and second pages.
2. Explain filter placement and why len(items)==limit does not by itself prove another page exists.
3. Implement **all_ids(rows, status, limit)** using your corrected page function, without duplicates or an infinite loop. Empty data returns []. In this exercise data does not change during pagination. Discuss one limitation of offset pagination if it did.
