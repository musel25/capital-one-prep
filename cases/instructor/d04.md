# Solución — Caso: navegar disputas sin perder resultados

No leer antes de guardar predicción y terminar el intento.

## Resultado razonado
Actual: **{'items':['d2'],'total':1,'next_offset':None}**. Se recortó [d1,d2] antes del filtro y el consumidor cree que terminó. Correcta página1: **{'items':['d2','d3'],'total':4,'next_offset':2}**. Página2: **{'items':['d5','d6'],'total':4,'next_offset':None}**. La última página está llena y aun así no hay siguiente.

```python
def page(rows, status, offset, limit):
    matches = sorted((r for r in rows if r["status"] == status),
                     key=lambda r: (r["created"], r["id"]))
    items = [r["id"] for r in matches[offset:offset+limit]]
    end = offset + len(items)
    return {"items": items, "total": len(matches),
            "next_offset": end if end < len(matches) else None}

def all_ids(rows, status, limit):
    out, offset = [], 0
    while True:
        result = page(rows, status, offset, limit)
        out.extend(result["items"])
        if result["next_offset"] is None:
            return out
        offset = result["next_offset"]
```
all_ids devuelve **['d2','d3','d5','d6']** y vacío devuelve []. offset=9 produce items=[], total=4, next=None. Orden estable por ID resuelve el empate. Una página cuesta O(n log n); esta implementación de all_ids repite trabajo por página: O(p n log n), no O(n). Optimización posible: preparar el conjunto una vez. Con inserciones simultáneas, offsets pueden saltar o repetir filas; hace falta snapshot o contrato de cursor. Métricas: tiempo hasta encontrar una disputa; riesgo: coincidencias inaccesibles.
