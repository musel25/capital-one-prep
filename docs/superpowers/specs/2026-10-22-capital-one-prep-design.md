# Capital One Prep design

Approved intent: user asked for a Grind Recall-like task page plus a local GitHub repository where they practice in their own editor and the assistant can inspect attempts. User confirmed four hours daily and authorized implementation on October 22, 2026. Project name capital-one-prep accepted by proceeding after the proposal.

## Product
Ten dated days, October 23 through November 1, 2026 inclusive, each exactly 240 scheduled minutes in America/Tijuana. Spanish guidance, English interview prompts (builder assumption communicated earlier). Homepage opens the appropriate day, clamps to first/last outside the range, labels before/after range honestly, and allows selecting any day. Sidebar/calendar, agenda rows, task detail, checklist, phase timer, notes, completion, progress export/import. Display pending previous tasks without automatic carry-over. No spaced repetition. Distinguish completed, independently completed, assisted and incomplete; completion is not readiness.

A task has a complete brief, objective, steps, duration, deliverables, evaluation rubric, optional hints, sources and optional answer key. Cases require a saved prediction before revealing solutions and are practiced without running code. Mock answers must remain unrevealed until the attempt. The app cannot verify local code execution; completion is self-reported. Browser-local notes persist, export/import is explicit and validated; private data must not enter Git or deployment. Export commands/results can be kept in private/ for assistant review.

## Practice
The editor stays local. Python projects use uv. CLI list/start/check creates unique ignored attempts folders, never overwrites or resets learner work. Bug and feature tasks are independent clean copies; instructor answers/tests must stay out of attempt folders. Twenty task IDs d01-bug,d01-feature through d10-bug,d10-feature. First days allow guided investigation; later rounds use 20 min task, 5 min explanation, clean copy, 20 min task, 5 min explanation. Tested faulty starters plus reference solutions establish intended defects and feature contracts. At least two distinct project contexts, multi-file app including an API and a small UI, and later unfamiliar mocks. The user receives symptoms and requirements, not defect locations.

Themes: transactions ordering/filtering, transfer atomicity/history, cashback/limits, pagination/metadata, refunds/grouping, frontend/backend contract, AI recovery, technical business rules, team/conflict/help/status quo/learning/AI behavioral stories. Targeted algorithm practice is subordinate to applied programming. Existing posted cases are learning examples; mock rules and data must differ. No personal story is invented. Source claims distinguish official documentation from anonymous testimony. Exact tool, timing and interview setup remain unconfirmed for this user's invitation.

## Architecture and ownership
One new repo, React + TypeScript + Vite frontend at web/, content in curriculum/plan.json, Python CLI scripts/practice.py and exercise packages in exercises/. Static deployment alongside the user's existing site at https://timer.musel.dev/grind/capital-one/; same design vocabulary as Grind Recall, isolated local state and separate path. No account/backend changes. Local progress only in v1, clearly labeled; export enables backups and transfer. Deploy using versioned static releases and nginx config validation, preserve existing routes and allow rollback.

Content contract: plan.json root {title, startDate, endDate, timezone, dailyMinutes, days, sources}. Day {date,title,focus,blocks}. Block {id,title,kind,minutes,summary,content,deliverables,rubric,hints?,solution?,prompts?,labs?,phases?,sources?}. kind is technical|case|behavioral|python|reflection. content/solution are Markdown strings. labs is array of task ID strings. phases array {title,minutes}. sources contains IDs of root source entries {id,title,url,level,note}; level official|testimony|practice|repository. Every block id globally unique. Each day sums to 240. Every task runnable before Day 1 begins; optional exercises are clearly separate from the required 240 minutes.

## Visual
Familiar calm blue/white planner: ink #19273b, blue #375dcc, pale background #f6f8fc, muted #68778b, green #26745a. DM Sans with system fallback. Desktop sidebar with dates, main day agenda and a compact next-action panel. Task drawer/dialog with readable prose, code examples, phases and notes. Mobile single column with horizontal date selector. No hero marketing, giant stats or readiness percentage. Progress numbers are time/task counts only.

## Verification
Tests cover date edges/timezone, 240-minute content completeness, lab references, progress validation, export/import, corrupt storage, preservation of notes and attempts, and timer pause/restore. Python verifies fresh starts, no overwrite, faulty versus fixed behavior, and no instructor leakage. Production build, responsive inspection if browser available, live HTTP/asset checks. Independent design and final code review. No changes to other projects' user work.
